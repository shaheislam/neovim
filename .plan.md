## Key Decisions

- The crash is caused by the locked `nvim-treesitter` markdown injection query still using `#set-lang-from-info-string!`, which is incompatible with Neovim 0.12's capture handling in this path
- Prefer a repo-local markdown query override over a broad plugin update because the failure is isolated and Neovim 0.12's runtime already provides the correct query shape
- Moved from a file-based query override to `vim.treesitter.query.set()` in `lua/plugins/treesitter.lua` because this worktree is not the active `~/.config/nvim` target on disk, so a plain `queries/` file here would not affect the running editor

## Failed Approaches

- Added `queries/markdown/injections.scm` in this worktree first, but it did not affect the active editor because `~/.config/nvim` currently points at a different config tree (`~/dotfiles/.config/nvim`), so Neovim never loaded the file from this repo

## Success Criteria

- Markdown buffers with fenced code blocks no longer trigger the `node:range` Treesitter error
- Headless Neovim startup remains clean
- The cause and fix are captured in beads and this session plan

## Current State

Neovim is at `0.12.1`. `lua/plugins/treesitter.lua` now installs a markdown injection query override via `vim.treesitter.query.set()` after `nvim-treesitter` setup, forcing the Neovim 0.12-compatible `@injection.language` capture even when the lockfile still points to the older plugin revision. Headless validation using this repo's `init.lua` shows the active captures are `injection.language` and `injection.content`, and parsing a fenced Markdown code block no longer crashes.
