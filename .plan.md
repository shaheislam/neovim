## Current State

Sidekick NES experiment is now configured for automatic suggestions again. Blink `<Tab>` is intended to prefer a visible completion menu first, then Sidekick NES / Copilot inline edits, then normal tab fallback.

Created `sidekick_nes_workflow_lab.go` as a disposable Go buffer for validating Blink completion priority, Copilot inline completion, Sidekick NES local next-edit behavior, and LSP rename as the semantic-refactor baseline. The file formats and runs standalone with `go run sidekick_nes_workflow_lab.go`.

Added `:SidekickNesDebug` and `<leader>asd` to request the raw Copilot `textDocument/copilotInlineEdit` response and display `err`, `ctx`, raw edit count, and raw response in a scratch split. Use this to distinguish empty Copilot NES responses from Sidekick filtering/discarding returned edits.

Fixed repeated NES debug runs by giving each scratch debug buffer a unique name, avoiding `E95: Buffer with this name already exists`.

Pinned `opencode.nvim` to port `4096` with a readiness-aware port resolver. The `server.port` config is now a function that polls `curl http://127.0.0.1:4096/path` every 500ms for up to 30s after starting the terminal. This prevents the `No opencode responding on port: 4096` error on cold starts — the first keypress starts OpenCode and waits until the server is actually listening before sending the prompt or command. The local server process listens as `ocv` on `127.0.0.1:4096`, which caused opencode.nvim's process-name discovery (`opencode.*--port`) to miss it and report `No opencode processes found` for `<leader>ao*` actions.

Fixed named OpenCode prompt keymaps by resolving entries from `require("opencode.config").opts.prompts` before sending them. The installed `opencode.nvim` public API currently sends literal strings passed to `require("opencode").prompt()`, so mappings like `<leader>aoe` and `<leader>aod` were appending `explain` / `document` instead of expanding to prompts with `@this` / `@diagnostics` context placeholders.

Added explicit no-op prefix mappings for `<leader>a`, `<leader>ao`, and `<leader>as` so AI group prefixes cannot fall through to normal-mode commands on timeout (`<leader>a` previously replayed `a` and entered insert mode).

Added a local Noice UI guard for bare Neovim 0.12 UI events such as `restart`. Current Noice expects grouped events like `msg_show` and errors when concatenating a nil event type; the guard returns nil for untyped events before Noice routes them.

Extended `opencode.nvim` `/tui/publish` calls from the plugin's hardcoded 2 second curl timeout to 10 seconds by overriding `tui_append_prompt` and `tui_execute_command` locally. This addresses intermittent `curl: (28) Operation timed out after 2006 milliseconds` errors when the OpenCode TUI is briefly busy while appending prompts or running actions.

OpenCode prompt and command keymaps now wait for `require("opencode.server").get()` before sending requests. Visual/current context is captured immediately via `opencode.context` before the async wait, then the prompt/command is sent after a short readiness delay so selections are preserved while avoiding `/tui/publish` requests during server startup.

Sidekick is now exposed as NES-only in local config. The duplicate Sidekick CLI mappings and custom CLI tool/prompt config were removed, leaving OpenCode as the sole agent/context workflow surface and `<leader>as*` for Next Edit Suggestions only.

Audit complete. Highest-value gaps were `lua/plugins/kubectl.lua`, missing health checks, sparse LuaCATS coverage on custom modules, missing config validation, stale README content, and no CI beyond Docker image publishing.

DiffView migration is on the maintained `dlyongemallo/diffview.nvim` fork with the prior expanded fold behavior pinned. Validation found one local toggle bug in the custom conflict auto-switch watchers; deferred reopen callbacks now re-check `vim.g.diffview_auto_switch`, so `:DiffviewAutoSwitchToggle` actually disables conflict auto-switching after the view is already open.

Single-file `:DiffviewFileHistory` warnings on merge commit `16cbef1018...` were traced to `diff_merges = "combined"`: Git can emit `--numstat` lines without matching `--raw` entries for some merge commits, which makes DiffView's file-history parser skip them. The local workaround is to use `diff_merges = "first-parent"` for single-file history, which restores clean file-history output without changing repo history.

DiffView follow-up now adds three opt-in workflow improvements: persisted reviewed-file selections, a stash-history entrypoint, and an explicit `DiffviewSetRevs` command so an open review can be retargeted in place when only the revision range changes.

The reviewed-file helpers are now reachable from the existing git namespace via `<leader>gr` for the reviewed list and `<leader>gX` for clearing marks.

Oil-compatible file browsing is now provided by `barrettruth/canola.nvim` instead of `stevearc/oil.nvim`. The main plugin spec and the zoxide integration dependency both point at Canola, and `lazy-lock.json` now locks `canola.nvim` with no remaining `oil.nvim` lock entry. Local integrations still use the upstream-compatible `require("oil")`, `:Oil`, `oil://`, and `filetype=oil` surface.
