# Plan: TASK

## Objective

Align this Neovim repo with the dotfiles hook-first workflow model so Neovim acts as a context router, `.plan.md` stays the steering control plane, and the AI tools have clear ownership across learning, routing, investigation, delivery, and review.

## Approach

1. Add a repo-local workflow contract that explains how this repo should use plans, bridge state, plugins, and review surfaces together
2. Add practical recipes so the intended `CodeCompanion -> opencode`, `CodeCompanion -> claude-code`, and `agentic -> opencode` flows are easy to reuse
3. Make `CodeCompanion` a clearer front-end router with reusable workflow prompts for bounded and larger handoffs
4. Improve `opencode.nvim` keymaps for bounded context packs and session hygiene
5. Update top-level docs so future sessions discover the workflow contract from `CLAUDE.md` and `AGENTS.md`
6. Validate the docs and Neovim config headlessly

## Progress

- [x] Investigation / current workflow inspection
- [x] Implementation (workflow docs and opencode ergonomics)
- [x] Validation

## Key Decisions

- The repo should follow the dotfiles control-plane model instead of inventing a separate plugin-centric orchestration layer.
- `.plan.md` remains the task control plane, while bridge state, diagnostics, quickfix, and git diff are the editor-state inputs.
- `CodeCompanion` owns learning and routing, `agentic.nvim` owns investigation, `opencode.nvim` owns bounded execution, and `claude-code.nvim` owns larger delivery loops.
- The highest-value missing Neovim ergonomics are explicit context-pack entrypoints and session controls for `opencode.nvim`.
- `CodeCompanion` should expose reusable handoff workflows so routing does not depend on ad-hoc prompts.

## Success Criteria

- The repo documents a clear AI workflow contract under `.claude/context/`
- `CLAUDE.md` and `AGENTS.md` both point to the workflow contract and usage model
- `CodeCompanion` exposes reusable router workflows for planning, `opencode`, and `claude-code`
- `opencode.nvim` exposes direct keypaths for buffer, visible-window, and quickfix context plus session control
- Headless validation passes for the updated plugin config and docs state is clean

## Current State

This repo already had the raw building blocks: `claude-bridge.lua`, hotreload, `.plan.md`, `CodeCompanion`, `agentic.nvim`, `opencode.nvim`, `claude-code.nvim`, diagnostics, and diff tooling. The missing piece was an explicit operating model telling users and agents how those parts should work together.

The implementation adds that model and a practical recipes layer under `.claude/context/`, while also making `opencode.nvim` easier to use as a bounded executor with explicit context packs and session hygiene commands. `CodeCompanion` now also exposes router workflows that turn the current buffer or visual selection into a routing brief, an `opencode` handoff brief, or a larger `claude-code` delivery brief.

Validation passed with `luac -p lua/plugins/opencode.lua`, `nvim --headless -u init.lua -c "qa!"`, and `git diff --check`. The only merge-marker grep hit left in the worktree is the intentional separator line in `scroll-test.txt`.

- Letting chat history become the source of truth: rejected because this repo already has stronger shared-state surfaces in `.plan.md`, bridge state, diagnostics, quickfix, and git diff.
