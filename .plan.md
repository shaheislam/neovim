# Plan: TASK

## Objective

Stop the visible terminal freeze that happens when `prefix+x` triggers session synthesis for Obsidian, while keeping the sync to `~/obsidian` running in the background so the interactive tmux/Neovim workflow stays responsive.

## Approach

1. Trace the exact `prefix+x` binding and cleanup path to confirm where tmux is waiting
2. Patch the cleanup flow so synthesis is detached from tmux control flow and redirected to logs instead of the active terminal
3. Validate the changed scripts with focused shell checks and smoke tests, then record the root cause and behavior change

## Progress

## Key Decisions

- The user-facing freeze is being treated as a tmux cleanup problem in `~/dotfiles`, not as a Neovim mapping problem in this repo, because `prefix+x` is defined in `~/.tmux.conf` and routes into worktree cleanup scripts there.
- The safest fix is to detach synthesis at the cleanup boundary and redirect output to logs, rather than changing the synthesis script semantics for every caller.

## Success Criteria

- `prefix+x` no longer visibly freezes tmux while session synthesis runs
- Session synthesis still writes to `~/obsidian` asynchronously
- The cleanup path preserves failure visibility through log output instead of the active terminal
- Focused validation passes for the edited shell/tmux scripts

## Current State

Tracing showed that `prefix+x` is a tmux binding in `~/dotfiles/.tmux.conf`, not a Neovim keymap in this repo. It calls `~/dotfiles/scripts/tmux/tmux-kill-pane-cleanup.sh`, which kills the pane and backgrounds `tmux-worktree-cleanup.sh` when closing the last pane.

`tmux-worktree-cleanup.sh` then runs `session-synthesize.sh` before worktree removal. The visible pause came from two coupling points: the tmux bindings for `x`/`X` used foreground `run-shell`, and the cleanup path allowed synthesis output to stay attached to the invoking terminal path.

The fix is now in place in `~/dotfiles`: `prefix+x` and `prefix+X` use `run-shell -b`, the last-pane wrapper launches cleanup via `nohup` with stdin detached, and the synthesis step logs to `/tmp/tmux-worktree-cleanup.log` instead of the active terminal.

Focused validation passed: `bash -n` succeeded for both cleanup scripts, `tmux -L synthfreeze-test -f ~/.tmux.conf start-server` loaded the tmux config, `tmux ... list-keys` confirmed backgrounded `run-shell -b` bindings for both `x` and `X`, and `git diff --check` passed in both repos.

## Failed Approaches

- Looking for the cause inside the Neovim repo first: rejected because no `C-s x` or synthesis mapping exists here; the actual binding lives in `~/dotfiles/.tmux.conf`.
