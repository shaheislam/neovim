## Key Decisions

- The deprecation is not from the repo's `client:request(...)` calls; it is triggered by `blink.cmp` using `client.request(...)` dot syntax under Neovim 0.12
- Fix the warning by disabling Blink completion in prompt-style buffers, which do not need LSP completion, instead of patching third-party plugin code outside the repo

## Success Criteria

- `gwtt-prompt` editing no longer surfaces the deprecation warning
- Blink remains enabled for normal editing buffers

## Current State

Investigation found that entering change mode in the prompt buffer triggers Blink completion, and Blink's installed LSP source still uses `client.request(...)` dot syntax. The repo fix is in place: `lua/plugins/blink-cmp.lua` now disables Blink in prompt-style buffers such as `gwtt-prompt`, and headless syntax/startup checks passed.

## Failed Approaches

- Replacing the repo's `client:request(...)` calls would not fix this warning because Neovim only deprecates dot-call usage (`client.request(...)`), and the repo code already uses colon syntax.
